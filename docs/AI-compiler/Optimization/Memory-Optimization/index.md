# Memory Optimization（内存优化）

> **定位**：贯穿 AI 编译器**全编译栈**的横切优化。它既在图级做张量生命周期分析与复用，也在算子级做共享内存分块，更在后端做访存对齐——**核心目标是降低峰值显存占用、打满显存带宽**。在大模型场景下，"能不能跑起来"往往比"跑多快"更重要，而这直接由内存优化决定。

## 一、深度学习为什么内存吃紧

```
关键事实：
  · 模型参数：7B ≈ 14GB (FP16)  →  70B ≈ 140GB
  · 激活值（训练）：反向传播需要保存所有前向激活
  · KV Cache（推理）：随序列长度线性增长
  · 优化器状态（训练）：Adam 需要 2 倍参数量的额外空间

→ 显存往往比算力更早成为瓶颈
```

## 二、核心技术

### 2.1 内存复用（Memory Reuse）与内存池化

基于**张量生命周期分析**，让不再使用的张量的显存被后续张量复用。

```
张量生命周期分析：
    t1 ─────┐(活跃)
            └─死亡后，其内存可给 t3 复用
    t2 ──────────┐
    t3      ┌────┘ ← 复用 t1 的内存块

本质：图着色 / 区间调度问题（类似寄存器分配）
```

**内存池（Memory Pool）**：预分配大块内存，避免频繁 `cudaMalloc/cudaFree`（每次调用都是同步操作，昂贵）。

### 2.2 静态内存规划（Static Memory Planning）

编译期**预分配所有张量内存**，运行时零动态分配，消除调度开销。

```
编译期：
  1. 拓扑排序 + 生命周期分析
  2. 求解"区间图着色" → 得到复用方案
  3. 决定一整块 workspace buffer 的布局

运行时：
  · 每个张量直接使用 workspace 中的固定 offset
  · 无 malloc/free 调用
```

### 2.3 In-place 操作（原地计算）

对**逐元素算子**，直接在输入张量上写结果，不额外分配内存。

```
非 in-place：  y = ReLU(x)     → 分配新内存给 y
in-place：     x = ReLU(x)     → 直接覆盖 x（输入不再需要时）

适用：ReLU、Add、Dropout 等 elementwise 算子
约束：输入张量后续不再被使用
```

### 2.4 重计算（Gradient Checkpointing / Recomputation）

**用计算换内存**——训练时不保存所有中间激活，反向传播时重新计算。

```
标准反向传播：保存所有前向激活 → 内存爆炸
重计算：      只保存少量检查点，需要时重算
    → 内存大幅下降，计算量略增（典型：省 O(n)→O(√n) 内存）
```

> **大模型训练的救命技术**——没有它，很多大模型根本训不起来。

### 2.5 访存对齐与合并（Coalescing）

调整内存**地址与访问顺序**，适配硬件突发传输（burst）特性，打满显存带宽。

```
Warp 内 32 个线程同时访问显存：
  · 合并访问：32 线程访问连续 128 字节 → 1 次事务 ✅
  · 非合并：  32 线程跨步访问          → 多次事务 ❌

优化手段：
  · 数据结构 AoS ↔ SoA 转换
  · 内存 padding 避免 bank conflict
  · 使用 128-bit 加载指令（float4）
```

### 2.6 Layout 与访存模式优化

不同硬件、不同算子偏好不同内存布局：

```
CPU 常偏好 NCHW，GPU/TensorCore 常偏好 NHWC
INT8 场景常见 NCHW4c、NCHW32c（channel 分块布局）

编译器要做的：
  1. 为每个算子选择最优 layout
  2. 通过 layout 传播消除冗余 transpose
  3. 必要时插入 layout 转换算子
```

## 三、大模型场景专项

大模型带来了全新的内存挑战，进一步的专项技术详见 [LLM-Specific-Optimization](../LLM-Specific-Optimization/index.md)，本节仅列关键要点：

- **KV Cache 管理**：PagedAttention（vLLM）用"虚拟内存"思想管理非连续 KV 块，大幅提升碎片利用率
- **KV Cache 量化**：INT4/INT2 量化，线性降低长序列显存占用
- **Prefix Caching**：识别并复用系统提示、RAG 上下文的 KV 结果

## 四、与其它优化的关系

```
图级 ──── 张量生命周期 / in-place / 布局传播
   │
   ├─ 算子级 ──── 共享内存分块 / 寄存器复用
   │
   └─ 后端 ──── 访存合并 / bank conflict 消除

任何一层做好了都能省显存，但真正的效果来自"贯穿全栈的协同"
```

## 五、实践清单

- 训练场景优先：静态内存规划 + 重计算 + 混合精度
- 推理场景优先：静态内存规划 + KV Cache 管理 + 量化
- 用 `torch.cuda.memory_summary()` / Nsight Systems 定位峰值
- 关注"临时张量"（intermediate）—— 它们往往是峰值内存的元凶，也是融合优化的重点靶子
