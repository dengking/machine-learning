## Programming model&IR

Tile IR 与 PTX 是 CUDA 平台下对应两种不同编程范式的底层中间表示，二者定位对等、范式互补，最终都会编译为 GPU 硬件可执行的 **SASS 指令**。核心差异对比如下：

| 对比维度 | PTX                        | Tile IR                                   |
|:---- |:-------------------------- |:----------------------------------------- |
| 核心定位 | SIMT 编程模型的虚拟指令集，CUDA 生态的基石 | Tile 分块编程模型的虚拟指令集，分块范式下的对等PTX             |
| 执行单元 | 单线程，以 warp（32线程）为硬件调度单位    | tile-block（逻辑分块），无显式线程概念                  |
| 编程视角 | 单线程**标量**视角，定义每个线程的执行逻辑    | 分块**张量视角**，仅定义数据分块与分块内计算                  |
| 类型系统 | 标量为核心，向量/张量运算属于扩展指令        | 原生张量类型系统，所有值均为多维 tile                     |
| 内存模型 | 显式内存层级，手动管理共享内存、搬运与同步      | 内存层级抽象，自动处理共享内存、TMA与同步                    |
| 硬件适配 | 开发者手动分块、调度张量核心、适配架构        | 编译器自动映射到Tensor Core、TMA、寄存器等资源            |
| 架构兼容 | 全代际 NVIDIA GPU 支持，向前兼容性极强  | CUDA 13.2 起支持 Ampere/Ada/Blackwell，仅覆盖新架构 |
| 技术底座 | 类汇编的文本/二进制指令格式             | 基于 MLIR 的 cuda_tile 方言，SSA 形式             |
| 典型场景 | 通用并行计算、不规则算法、传统 CUDA 程序    | 张量计算、深度学习算子、规整分块型科学计算                     |

---

### 1. 执行模型：本质范式差异

这是两者最核心的区别，对应完全不同的硬件抽象：

- **PTX** 严格遵循 SIMT（单指令多线程）模型：程序员从单个线程的视角编写代码，硬件以 warp 为单位调度32个线程同步执行。线程的 grid/block 层级、**分支发散**、线程间同步都需要开发者显式控制，性能上限高度依赖开发者对硬件的理解深度。
- **Tile IR** 采用分块中心模型：基本执行单元是逻辑上的 tile-block，开发者只需要描述“对多大的分块做什么计算”，完全不需要感知线程、warp 的存在。分块到线程、warp、SM 的映射完全由编译器自动完成，天然规避了**分支发散**、线程同步等SIMT常见痛点。

### 2. 数据与类型系统：标量 vs 张量

- **PTX** 是标量指令集，所有运算基于标量寄存器，向量（如 `float4`）、矩阵运算（`wmma`）都属于扩展指令，需要手动调用、手动对齐分块尺寸。
- **Tile IR** 原生基于**张量**设计，所有值均为静态形状的多维 `tile` 类型，内置完整的张量运算指令（加载、存储、逐元素运算、矩阵乘累加等），张量核心的 MMA 操作是一等公民，无需手动拆分为低维指令。

### 3. 内存模型：显式管理 vs 自动调度

- **PTX** 向开发者完全暴露 GPU 的内存层级：全局内存、共享内存、本地内存、寄存器堆，开发者需要手动分配共享内存、编写全局-共享的数据搬运代码、插入同步原语，内存一致性完全由代码保证。
- **Tile IR** 通过 `view`（内存视图）抽象内存层级，开发者仅需声明对内存分块的读写，底层的全局内存访问、TMA（张量内存加速器）调度、共享内存分配、数据流水线、线程间同步全部由编译器自动处理。

### 4. 可移植性与硬件适配

- **PTX** 的可移植性是**指令级兼容**：同一份PTX可以在新架构上运行，但要发挥新硬件（如新张量核心、TMA）的性能，往往需要重写优化代码。
- **Tile IR** 的可移植性是**分块级兼容**：同一份Tile IR字节码可以在多代支持的GPU上运行，编译器会针对当前架构自动选择最优的映射方式（分块大小、流水线深度、张量核心调用方式），架构升级时无需修改上层代码即可获得性能提升。

### 5. 生态与目标用户

- **PTX** 是CUDA生态的通用底层标准，面向所有CUDA开发者，配套调试、分析工具链极其成熟，覆盖从通用计算到高性能计算的全场景。
- **Tile IR** 是面向编译器与框架开发者的专用IR，主要作为Triton等深度学习DSL、高性能算子库的编译后端，普通开发者通常通过上层语言（cuTile Python、Triton）间接使用。

---

### 总结

二者并非替代关系，而是CUDA平台对不同编程范式的底层支撑：

- 处理不规则、通用的并行任务，传统SIMT模型+PTX仍是最优选择；
- 处理深度学习、科学计算等规整的张量分块任务，Tile IR能以更低的开发成本获得跨架构的高性能。
